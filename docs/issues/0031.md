# 0031 — Decide whether a world-space decal's endpoints are snap targets

**Status:** Open
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0027.md" title="0027 — Let a world-space decal be picked in the scene view">0027</a>, <a href="0021.md" title="0021 — Let a point be placed by dragging it in the scene view">0021</a>

> A drag snaps to the endpoints of the shapes around it. A world-space decal
> contributes none, so a drag near one snaps to nothing. Making it contribute
> them is small; deciding whether it should is not.

## What is true today

`snapPoints` gathers candidates from `scene.decals` and from
`decalPointsUnder(scene.frames, …)` — the shapes that exist once the scene is
built. A world-space decal is not one of those: it is held as a maker and made
afresh from each tick, which is why [0027](0027.md) had to hand back makers
rather than shapes to make one clickable.

So a world decal is now pickable and is still not snappable, and the gap is
visible: a person can click the endpoint of a `<WorldLine>` to select it, and
then find that dragging something else near that same endpoint does not catch.

## The question

**Should the endpoints of a decal that moves with the rig be snap targets at
all?**

A snap target is a place a person is putting something *permanently* — the
value lands in the document and stays there. A world decal's endpoints are
somewhere else on the next tick, because at least one of them is an expression
over a frame's pose. Snapping to one records where the rig happened to be at
the moment of the drag, which is either exactly what was wanted or a value
that silently means nothing, and which of those it is depends on what the
person thought they were pointing at.

Two answers are defensible, and they are not the same feature:

- **Snap to the made shape.** The endpoints of the decal as currently posed
  join the candidate set, and the dragged point takes their numbers. Small,
  consistent with every other shape, and records a coordinate that was true
  once.
- **Snap to the expression.** The dragged point takes the *expression* the
  world decal's endpoint was written with, so it keeps tracking the frame. Much
  the more useful of the two where it applies, and it is really a different
  feature — snapping one expression to another — which belongs with the rest of
  the expression work rather than here.

There is also a plain **no**: leave world decals out of snapping, and say so in
the doc, on the grounds that a moving target is not a place to put something.

## Why it is filed rather than done

Because the code is the easy half. Adding world decals to `snapPoints` is the
same shape of change as the pick was, and it would take about as long — but
which of the three answers above it should implement is a design call, and
implementing the first because it is the cheapest would quietly foreclose the
second.

## What happens if this is not done

A drag near a world-space decal's endpoints catches nothing, which is a small
inconsistency in a scene view where everything else snaps. Nothing is wrong;
one thing is missing, and it stays missing until the question above has an
answer.
