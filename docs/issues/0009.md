# 0009 — Centre the demo's view on the plot rather than on a hardcoded point

**Status:** Resolved
· **Kind:** Bug
· **Parent:** <a href="README.md" title="Issues">Issues</a>

> `App.jsx` built its view transform around `mat3.translation(300, 300)` — a
> fixed point, in a plot sized `width: 100%; height: 100%` of a flex item. In
> any window where the plot came out shorter than about 600px the whole scene
> was drawn below its bottom edge, and the demo rendered as an empty blue
> rectangle with no error and nothing in the console.

## Background

Noticed while comparing renderings for
[#14](https://github.com/kkroening/physm/pull/14), where the plot was blank on
both branches — which is what established it as pre-existing rather than a
regression, and is why it went unfixed at the time.

The scene was there the whole while. Reading the SVG showed real geometry at
`y = 300`, in an element 212px tall:

```
<line class="plot__line" x1="-3300" y1="300" x2="3900" y2="300" .../>
<g class="frame"><rect x="276" y="285.16687268232386" .../>
```

`.plot__svg` is `width: 100%; height: 100%` inside `.plot__main`, which is
`flex: 1` — so the plot's size is the window's, and a constant was never going
to be its centre.

## Resolution

A `useElementSize` hook backed by a `ResizeObserver`, and
`getViewXformMatrix(translation, scale, [width, height])` centring on the
element's midpoint. A `ResizeObserver` rather than a `resize` listener because
the plot also changes size when the surrounding layout does, with no window
event to hear.

**The hook uses `useLayoutEffect`, and measures once synchronously rather than
waiting for the observer.** An ordinary effect runs *after* the browser paints,
so an observer started there cannot report until the second frame — which would
make the first painted frame a view centred on the element's own corner, with
half the scene clipped. A layout effect runs before paint and its `setSize` is
flushed before paint, so that frame never reaches the screen.

The transform is its own module rather than a local in `App.jsx`. That was
forced by wanting a test: `App.jsx` is `.jsx` and `checkJs` is off, so nothing
in it is type-checked, and a non-component export beside a component trips
`react-refresh`. Extracting it makes the one piece of arithmetic in the app
both checkable and testable — and the four tests it now has all fail against
the hardcoded centre this replaces.

Verified in the running app rather than by inspection. The cart's centre tracks
the plot's midpoint exactly across a resize:

| plot | cart centre |
| --- | --- |
| 509 × 212 | (255, 106) |
| 466 × 474 | (233, 237) |

...and the demo is visible, and still animates.

`jsdom` implements no `ResizeObserver`, so `setupTests.js` stubs one. A stub
rather than a polyfill: nothing under test asserts anything about resizing, and
a real implementation would want a layout engine jsdom does not have. Elements
have no layout in jsdom at all, so they measure zero either way — which is why
the transform's behaviour at zero is pinned by a test of its own rather than
left implicit.
