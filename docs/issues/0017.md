# 0017 — Give the document a save format, since its own output cannot carry it

**Status:** Open
· **Kind:** RFC
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0016.md" title="0016 — Make the document a program rather than a drawing">0016</a>,
<a href="0014.md" title="0014 — An interactive scene editor that emits TSX">0014</a>

> The editor has no persistence at all: it opens on `starterDocument()` and the
> document lives in memory for the session. The emitted TSX looks like it could
> serve — but it cannot, and never could: `documentFrom` recovers a single
> definition, so any document with a scene *and* a component is already one-way.
> [0016](0016.md)'s expressions widen that gap rather than opening it. The
> document needs a format of its own, and what that is has not been decided.

## What is true today

`Editor` takes an optional `initialDocument` and otherwise calls
`starterDocument()`. There is no save, no load, no `localStorage`, no file
picker. Closing the tab loses the work.

It has been tolerable for an editor under construction, and it has been easy to
assume the emitted module would do at a pinch. **It would not, and does not
today.** `documentFrom` turns an element tree into a document of exactly *one*
definition:

```ts
return { definitions: [{ name: root, body: nodesFrom(element) }], root };
```

So a document holding a scene *and* a `Pendulum` — which is what the editor opens
with — cannot come back from its own output already. The emitter's own test knows
this and tests the right thing: `expectRoundTrip` evaluates the emitted source,
builds it, and compares the **scene** against the document's. It never asks for
the document back.

## What makes it pressing

[0016 page 4](0016/04-expressions.md) fixes the emitted form of an expression as
a **constructor call** — `mul(halfLength, 2)`, which builds an expression node
rather than a product — so that a signal, which has no value at emit time, can
survive as a graph.

That changes what is lost, and not by as much as it first appears. The
*operation* now survives into an element tree, because `mul` returns data. The
**reference does not**: a parameter is a value at call time, so by the time the
tree exists `halfLength` has been folded and what remains is `mul(4, 2)`. An
expression whose references are gone is a constant with extra steps, which is
the case that never needed recovering.

Parsing the source to get it back is the bidirectional problem
[0016 page 1](0016/01-overview.md) declines, deliberately and for good reasons.

So **emitted TSX is an export format, not a save format** — it always was — and
the document has no other.

## What has to be decided

- **The format.** The document is already plain data — definitions, nodes,
  `ComponentRef`s, prop values — so JSON is the obvious candidate. What is not
  obvious is `ComponentRef`, since both `core` and `imported` hold a live
  component function, and they are hard for different reasons:
    - A **core** ref needs a stable name against a closed set the binding
      exports. That is a lookup table, and the only question is what happens to
      a document naming a component a later binding has dropped.
    - An **imported** ref needs a **module specifier the document does not
      hold** — a gap that predates this issue, and one the frontier already
      records from the emitter's side, where the component's name under a
      production build would write both the wrong tag and the wrong import
      path. `emitScene` reconstructs the specifier at write time from a naming
      convention — a default import from a module of the component's own name,
      "this repo's convention -- one component per file, named for it" — which
      is fine for output a person reads and can fix. A save format inheriting
      it silently fails to reload a document whose components share a file. So
      either the document starts recording where a component came from, or
      reloading accepts the convention's limits; that is a decision about the
      document's shape rather than about the encoding.
- **Where it lives.** `localStorage` is the cheap answer and is per-browser. A
  file the person saves and opens is the durable one and needs a file picker.
  They are not exclusive.
- **Versioning.** The document's shape is about to change in at least five ways
  ([0016](0016.md)'s staging). A format introduced now will need to read what it
  wrote before each of them, which argues for a version field from the first
  commit rather than the first migration.
- **Whether the emitted TSX stays reachable as an import, and whether it says
  what it dropped.** It is genuinely useful for bringing a *hand-written* rig
  into the editor, and that use loses nothing: there were never any parameters
  to lose, so numbers are all there ever was.

  The case that turns is importing the editor's **own** output, which having a
  save format makes plausible for the first time — and most tempting at exactly
  the moment the save format has failed somebody. The document that comes back
  builds the identical scene, draws identically and simulates identically, while
  every parameter has collapsed to the number it held and every expression to
  the folded shape around it. **Nothing in the
  result signals the loss**, because scene equality is the one property emission
  guarantees and it is completely intact.

  So the open question is not only whether the door stays open but whether it
  announces the cost. Refusing a file recognisable as the editor's own output is
  one candidate; a warning that names what was flattened is another. Worth
  deciding rather than discovering — and not an argument against keeping the
  import, since the same property is what makes it safe in the direction it was
  built for.

## Why it is filed rather than solved

It is not blocking, and it is not new — the editor has run without persistence
throughout its construction, and nothing about [0016](0016.md)'s early steps
changes that. What changes is that the comfortable assumption underneath it
("we can always read the TSX back") turns out to be false now and more obviously
false later, so the decision wants making deliberately rather than the first
time somebody loses a scene.
