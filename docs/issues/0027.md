# 0027 — Let a world-space decal be picked in the scene view

**Status:** Resolved
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0016.md" title="0016 — Make the document a program rather than a drawing">0016</a>, <a href="0031.md" title="0031 — Decide whether a world-space decal&#39;s endpoints are snap targets">0031</a>

> A `<WorldLine>` drew, and clicking it did nothing. Every other shape in the
> scene view could be clicked to select the document node that put it there;
> this one could only be reached from the tree.

## What is true today

Clicking a world-space decal selects the node that wrote it, as clicking any
other shape does.

The editor leads a picked object back to a document node by identity:
`buildScene`'s `trace` records the trail of every object as it is built, and
the lookup is that object. A world-space decal has no such object. It is held
as a maker rather than as a shape, precisely because there is no pose at
assembly to make it from — so at the moment `trace` runs, the thing a person
would later click does not exist, and every tick makes a different one.

What is recorded, and what a hit hands back, is therefore the **maker**.
`trace` is told of the `WorldDecal` when the walk collects it, and `hitsAt`
makes each world decal from the tick it is given, tests it like any other, and
returns the maker of whichever was hit. The made shape stays anonymous, and
nothing has to be stable across poses.

## How it was closed

By the route above, in preference to the other shape available: a
back-reference on the made decal would have been smaller, and would have put
an editor concern inside a core type.

Two details worth keeping. A world decal is drawn after every other decal, so
it comes first among the shapes a click finds — a frame's gizmo still comes
before it, as it does before an ordinary decal, because the editor draws
gizmos over everything. And a maker that cannot answer — a frame id naming
nothing, a rig that has diverged — costs its own hit rather than the pointer:
this runs on every pointer move, and such a decal is not drawn either, so
there is nothing there to hit.

## What this did not settle

**Snap points**, which are [0031](0031.md) rather than the rest of this.
`snapPoints` reads `scene.decals` and each frame's, so a world decal
contributes none and a drag near one does not snap to its endpoints. It is the
same shape of fix as the pick and nothing blocks it — but it wants a decision
the pick did not, and a question is a different issue's shape than an
unfinished piece of work.
