# 0027 — Let a world-space decal be picked in the scene view

**Status:** Open
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0016.md" title="0016 — Make the document a program rather than a drawing">0016</a>

> A `<WorldLine>` draws, and clicking it does nothing. Every other shape in the
> scene view can be clicked to select the document node that put it there; this
> one can only be reached from the tree.

## What is true today

`hitsAt` gathers candidates from `scene.decals` and each frame's `decals`, and
returns the decal objects themselves. The editor turns a picked object back into
a document node by identity: `buildScene`'s `trace` records the trail of every
object as it is built, and the lookup is that object.

A world-space decal has no object to record. It is held as a maker rather than
as a shape, precisely because there is no pose at assembly to make it from — so
at the moment `trace` runs, the thing a person would later click does not exist,
and every tick makes a different one.

`snapPoints` is the same shape of problem: it reads `scene.decals` and each
frame's, and a world decal contributes no snap points.

## What has been done

**Clicking one selects it**, by the first of the two shapes below: `trace`
records the `WorldDecal` *maker* when the walk collects it, and `hitsAt` makes
each world decal from the tick it is given, tests it like any other, and hands
back the **maker** of whichever was hit. The made shape stays anonymous, and
nothing has to be stable across poses.

The alternative — a back-reference on the made decal — would have been smaller
and would have put an editor concern inside a core type.

Two details worth keeping. A world decal is drawn over the frames, so it comes
first in the hit order, which is what "topmost first" means. And a maker that
cannot answer — a frame id naming nothing, a rig that has diverged — costs its
own hit rather than the pointer: this runs on every pointer move, and such a
decal is not drawn either, so there is nothing there to hit.

## What is left

**Snap points.** `snapPoints` reads `scene.decals` and each frame's, so a world
decal contributes none — a drag near one does not snap to its endpoints. Same
shape of fix as the pick, and unblocked; it is separate here because snapping
wants a decision the pick did not: whether the endpoints of a decal that *moves
with the rig* are somewhere a person should be able to snap to at all, given
they are somewhere else on the next tick.

## What happens if the rest is not done

Less than when this was filed. A world-space decal is now selectable by
clicking it, as every other shape is. What it is not is a thing a drag snaps
to, which is a smaller gap and a real question rather than an oversight.
