# 0027 — Let a world-space decal be picked in the scene view

**Status:** Open
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0016.md" title="0016 — Make the document a program rather than a drawing">0016</a>

> A `<WorldLine>` draws, and clicking it does nothing. Every other shape in the
> scene view can be clicked to select the document node that put it there; this
> one can only be reached from the tree.

## What is true today

`hitsAt` gathers candidates from `scene.decals` and each frame's `decals`, and
returns the decal objects themselves. The editor turns a picked object back into
a document node by identity: `buildScene`'s `trace` records the trail of every
object as it is built, and the lookup is that object.

A world-space decal has no object to record. It is held as a maker rather than
as a shape, precisely because there is no pose at assembly to make it from — so
at the moment `trace` runs, the thing a person would later click does not exist,
and every tick makes a different one.

`snapPoints` is the same shape of problem: it reads `scene.decals` and each
frame's, and a world decal contributes no snap points.

## What it would take

The pick itself is easy — `hitsAt` already takes both halves of a tick, so it
could make each world decal and test it like any other. The identity is the
work:

- **Trace the maker, not the shape.** `trace` records the `WorldDecal` function
  when the walk collects it, and `hitsAt` returns something that carries which
  maker produced the shape it hit. The made decal stays anonymous, and nothing
  has to be stable across ticks.
- **Or give the made decal a back-reference** to the maker it came from, which
  is smaller but puts an editor concern inside a core type.

The first looks right and is not large. It is filed rather than done because it
is editor work and the change that introduced world-space decals was core and
binding work; doing both at once would have made one review into two.

## What happens if this is not done

A world-space decal is selectable from the tree and editable in the properties
pane, and clicking it in the drawing selects whatever is behind it. That is a
worse experience than every other shape has, and it is the kind of gap that
reads as a bug rather than as a boundary.
