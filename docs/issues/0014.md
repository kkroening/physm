# 0014 — An interactive scene editor that emits TSX

**Status:** Open
· **Kind:** RFC
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0005.md" title="0005 — Give JSX siblings their tree order, which effect registration cannot">0005</a>,
<a href="0006.md" title="0006 — Let a JSX rig be assembled without mounting a renderer">0006</a>,
<a href="0011.md" title="0011 — Give the binding a way to name a frame from outside the scene">0011</a>

> A four-pane editor — hierarchy, code, scene, properties, with a component
> library along the bottom — that builds a rig by direct manipulation and emits
> the `.tsx` you would have written by hand. One-way: the editor writes source,
> nothing reads it back.

**The verdict up front: this is more tractable than it sounds, and the reason is
that JSX is already a data literal.** `<RopeChain anchor={p} />` evaluates to
`{ type: RopeChain, props: { anchor: p } }` **without calling `RopeChain`**, so a
scene module's exported element tree *is* a document model — no parser, no
renderer, no round-trip machinery. The editor's hardest-sounding requirement is
the one React hands over for free.

The part that does **not** work as hoped is reflecting a component's props from
the function itself. That is not a gap to be engineered around; it is closed, and
[page 4](0014/04-metadata.md) argues that explicit metadata is the better answer
even in the world where reflection worked.

Three of the tracker's open RFCs turn out to be prerequisites rather than
neighbours — [0005](0005.md), [0006](0006.md) and [0011](0011.md) — each raised
independently, and each blocking a different pane. That convergence is the best
evidence available that this design is being discovered rather than invented.
