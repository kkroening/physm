# 0018 — Draw the expression graph, so the representation has to be honest

**Status:** Open
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0016.md" title="0016 — Make the document a program rather than a drawing">0016</a>

> A pane that draws a prop's expression as nodes and edges. Useful for debugging,
> and useful before that: **a graph you cannot draw is a graph you have stored
> wrongly**, so building the viewer early is a check on the representation
> rather than a reward for finishing it.

## Why early rather than late

[0016 page 4](0016/04-expressions.md) defers the graph pane — *"nothing about it
is blocked once the representation is a graph; it is a second renderer of stored
data, not a second source of truth"* — and that is true of the *feature*. It is
not true of the *pressure*.

An expression representation can look fine from the inside while being quietly
unreflective: sharing that exists in the evaluator but not in the stored form,
a node kind that carries its meaning in a side table, a reference that resolves
by scope-walking at evaluation time rather than by an edge. Each of those is
invisible to a test that only checks the expression *evaluates* correctly, and
each makes the graph undrawable without inventing information.

So the viewer earns its place as a **design check**: if drawing it requires
anything the representation does not already hold, the representation is wrong,
and that is much cheaper to learn while there are three node kinds than after
there are thirty.

It is also the fastest way to debug an expression that is wrong, which is the
ordinary reason to want it.

## What it is

A read-only pane, at first. Nodes for literals, references and operations;
edges for inputs; the shared subexpression drawn as one node with two outgoing
edges, because that is what makes sharing visible rather than asserted.

Editing it comes later or never — [0016 page 4](0016/04-expressions.md) wants
the graph editable eventually, and none of that is needed for either purpose
above. A viewer that cannot edit still catches an unfaithful representation on
the day it is written.

## When

**Standing fallback work.** It depends on the expression representation existing
and on nothing else, so it is the thing to pick up whenever the main line is
blocked — a decision waiting on a human, a review in flight, a question that
wants sleeping on. That is a better use for it than a scheduled slot, because it
stays useful at any point after expressions land and never becomes urgent.
