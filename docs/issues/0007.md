# 0007 — Settle whether authoring components should share names with the classes they wrap

**Status:** Resolved
· **Kind:** RFC
· **Parent:** <a href="README.md" title="Issues">Issues</a>

> Nine names now mean two different things each. `Scene`, `TrackFrame`,
> `RotationalFrame`, `BoxDecal`, `CircleDecal`, `LineDecal`, `Weight`,
> `CoincidenceConstraint` and `DistanceConstraint` are all both a class you
> construct and a component that describes one.
>
> This is public surface, so renaming later breaks everything written against
> it. Worth settling before the demo is migrated.

## Background

Raised during review of [#15](https://github.com/kkroening/physm/pull/15),
which introduced the components.

The diff already pays for the collision. Every new component module imports its
own subject as `CoreX`, and `Scene.test.tsx` opens with nine `Core*` aliases
before it can say anything. That is the cost at the first two call sites; it
recurs at every one, and in every stack trace and error message.

The distinction the collision hides is real: `new Scene({ frames })` takes
assembled objects, while `<Scene>` takes a description and hands one back
through a callback.

## The options

- **Leave it**, and rely on the import path to disambiguate. Defensible, and
  what several React bindings do. The `Core*` aliasing then becomes house style
  and should be recorded as such rather than reinvented per file.
- **Namespace the import** — `import * as physm from './react'`, so it reads
  `<physm.TrackFrame>`. Costs nothing at the definition site and disambiguates
  at every use.
- **Rename the components** — `<Track>`, `<Revolute>`, `<Box>`. Reads better as
  JSX than as an API, and gives up the one-to-one correspondence with the
  classes that [#15](https://github.com/kkroening/physm/pull/15) is at pains to
  establish and to test.

## A smaller, related thing

`src/react/index.ts`'s docstring calls the module `physm/react`, which is not
an importable specifier: the package is `physm-js`, private, with no `exports`
map. Harmless as shorthand, and it would read as a promise if the package were
ever published.

## Acceptance

A decision, recorded — and if it is "leave it", the `Core*` convention written
down somewhere an author will find it.

## Resolution

Neither "leave it" nor a wholesale rename. **Drop the suffix where JSX already
supplies it; keep the name where it is the concept.**

`<BoxDecal>` is redundant — in a scene, a `<Box>` is obviously a decal — so the
three decals become `Box`, `Circle`, `Line`, and both constraints drop theirs:
`CoincidenceConstraint` → `Coincidence`, `DistanceConstraint` → `Distance`.
That is five renames.

`Scene`, `TrackFrame`, `RotationalFrame` and `Weight` keep their names, because
there the noun *is* the concept in both layers and shortening it would lose
information rather than repetition. `<Track>` does not say what a track is.

That takes the collisions from nine to four, and removes them from the names
used most in a scene. The four that remain are the ones where a reader seeing
`Scene` in either layer is thinking about the same thing.

Done while the binding had no consumers, which is what made it free — the
issue's own "cheap now, expensive later" — and alongside the `Anchor` work in
[#21](https://github.com/kkroening/physm/pull/21), since both reshape the same
surface.

The `physm/react` shorthand stands, and is still not an importable specifier.
Worth revisiting only if the package is ever published.
