# 0024 — Say what unit an angle typed as an expression is in

**Status:** Open
· **Kind:** Bug
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0022.md" title="0022 — Decide whether the parameter types grow toward the prop kinds">0022</a>

> An angle prop is held in radians and shown in degrees: the field divides on
> the way in and multiplies on the way out. A *computed* angle skips both, so
> `45` in the same box means 45° and `30 + 15` means 45 **radians**. Nothing
> says which, and both are accepted.

## What is true today

`NumberInput` scales by `DEGREES` for `spec.kind === 'angle'`, so typing `45`
stores `0.7853…`. Typing `30 + 15` parses to `add(30, 15)` and stores it
unscaled, and the scene builds with an angle of 45 radians — a little over
seven full turns.

The two paths are one field, one keystroke apart. `45` and `45 + 0` differ by a
factor of 57.3 and neither is marked.

## Why it is not just a missing multiply

Wrapping the parsed node in `div(…, DEGREES)` would make the *number* right and
the stored graph wrong: what the document would hold is
`div(add(30, 15), 57.29…)`, which is not what anyone typed, and which the graph
viewer would draw and the emitter would write. The surface unit would have
leaked into the representation.

And it does not survive a parameter. `halfTurn * 2` cannot be scaled at the
field, because `halfTurn` is whatever the instance passes — a value the field
never sees. Scaling the expression would be scaling the wrong thing.

## What the answers look like

**Store the unit with the prop.** The document says the value is in degrees and
converts when it builds. That is honest and it is a change to what a prop
*is* — closely related to [0022](0022.md), which asks whether the parameter
types should grow toward the prop kinds, because `Angle` carrying a unit is the
same question.

**Or make the expression's unit explicit in the language.** `deg(30 + 15)` as
an operation, so the graph says what the surface meant. Small, and it makes
every angle expression wordier.

**Or refuse an expression on an angle prop** until one of the above lands,
which is the cheapest correct thing and the one that costs a person the least
surprise.

## What happens if this is not done

A rig with a typed angle expression is wrong by a factor of 57.3, builds
without complaint, and looks like a bug in the solver.
