# 0021 — Let a definition's parameters be reordered

**Status:** Open
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0016.md" title="0016 — Make the document a program rather than a drawing">0016</a>

> A definition's parameters appear as rows at the top of its tree, and can be
> added, edited and deleted there — but not moved. Every other row in that tree
> can be: Alt+↑/↓ moves a node among its siblings, and a drag does the same with
> the pointer. A parameter row answers neither, which reads as an omission
> rather than as a rule.

## What is true today

`ParameterRow` handles the navigation keys, `Enter`/`Space`, `Escape` and
`Delete`. It deliberately does not handle `Alt+↑`/`Alt+↓`, and it is not a drag
source or a drop target. The toolbar's ↑ and ↓ are driven by `selectedPath`, so
they are disabled while a parameter is selected.

Order is not cosmetic. It is the order the emitted signature binds:

```tsx
function Pendulum({ bob, heft }: { bob: readonly [number, number]; heft: number })
```

so moving one changes the generated source, and a reader of that source reads
the declaration block's order.

## What it would take

A `moveParameter(doc, definition, at, by)` beside `removeParameter`, and the
toolbar's ↑/↓ plus `Alt+↑`/`Alt+↓` routed to it when the selection is a
parameter rather than a node. None of it is hard.

**Drag is the larger half**, and is the reason this is filed rather than done.
`TreeDrag` is built around a `NodePath` — `dragging` is a path joined, and
`dropRefusal`, `dropPoint` and `onDropNode` all take paths — so a parameter
joining the same drag means either a second drag channel or widening that one
the way `Selection` was widened. Worth doing deliberately, and worth doing once
the declaration block holds more than parameters: [0016 page
3](0016/03-scope.md) has outputs, manipulators and force channels living there
too, and a drag that handles all of them is a different design from one that
handles parameters alone.

## What happens if this is not done

A parameter list is appended to, and the only way to change the order is to
delete and re-add — which a reference refuses until the reference is given a
value first. That is a real annoyance on a definition with several parameters
and no annoyance at all on one with two.
