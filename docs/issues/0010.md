# 0010 — Make a dead export a build signal rather than an eyeball finding

**Status:** Open
· **Kind:** Enhancement
· **Parent:** <a href="README.md" title="Issues">Issues</a>
· **Related:** <a href="0008.md" title="0008 — Delete `testutils.ts`, which nothing imports and the lint config misnames">0008</a>

> Nothing in the toolchain can see an exported symbol with no importer. Both
> unused-variable rules report unused *locals*, and `noUnusedLocals` is off in
> `tsconfig.json` and would not cover it anyway. So a module can survive with no
> consumer indefinitely, and the only thing that finds it is somebody reading.

## Background

Raised during review of [#20](https://github.com/kkroening/physm/pull/20).

`testutils.ts` outlived its last consumer, survived the TypeScript port, and was
eventually noticed by eye while auditing an unrelated lint entry. CI was green
throughout, and could not have been otherwise.

There is no backlog behind it — the reviewer checked, and every other module
under `physm-js/src` has at least one importer, with all four of `utils.ts`'s
exports reached. So this is about the next one.

It bears on something `CLAUDE.md` already describes as in progress: `utils.js`
being dismantled a piece at a time. Dismantling is exactly the process that
leaves orphans, and `testutils.ts` was one of them.

## Proposal

A dead-export check as a lint step — [`knip`](https://knip.dev) or
[`ts-prune`](https://github.com/nadeesha/ts-prune). `knip` is the more current
of the two and also reports unused files and unused dependencies, which is the
same class of finding.

Two things worth deciding rather than assuming:

- **Where it runs.** CI as its own step, beside the format check, matches how
  the other conventions ended up enforced ([0001](0001.md)).
- **What counts as a false positive.** An export used only by tests, an entry
  point, and a type re-exported for a consumer that does not exist yet are all
  legitimate. A check that has to be argued with every time is one that gets
  removed.

## Acceptance

Deleting the sole importer of any module makes a CI job fail rather than
producing a green build and a file nobody reads.
